slivar rules for CNVs: assets/cnv-slivar-functions.js
─────────────────────────────────────────

The authoritative description is the maps at the top of assets/cnv-slivar-functions.js (every
step of has_moi_call() / cnv_moi() and of cn_po_origin(), plus the shared building blocks), and
its two tables: TRIO_TABLE and X_LINKED_CALLS. What every named scenario produces is in
assets/moi_scenarios.md, generated by assets/cnv-slivar-moi-harness.js. This file is only an
overview.

SLIVAR_EXPR (conf/modules.config) calls two classifiers. Both decide per child; the mode of
inheritance is wired like the SNV pipeline, as one --family-expr per tag:

  --family-expr  <tag>:has_moi_call(fam, variant, "<tag>")        true if any child of the family
                                                                 gets that call from cnv_moi();
                                                                 valued with the affected members
  --sample-expr  po_*:cn_po_origin(sample, variant) == "<origin>" parent of origin, valued with
                                                                 the children it resolves

  14 MoI tags   denovo, denovo_suspect, inherited_maternal, inherited_paternal, recessive,
                recessive_lowconf, possible_denovo, possible_inherited_maternal,
                possible_inherited_paternal, inheritance_unresolved, mendelian_inconsistent,
                unknown_cn, and on non-PAR chrX x_linked_denovo, x_linked_recessive
  8 PO tags     po_mother, po_father, po_both, po_ambiguous, po_denovo, po_possible_denovo,
                po_possible_mother, po_possible_father (the SNV pipeline's names)

A family with several affected children can carry several MoI tags (one per child's call); the
po_* tags say which child is which. The harness checks that conf/modules.config has one
expression per call and parent of origin.

has_moi_call(fam, variant, tag)      true as soon as one member's cnv_moi() is <tag>
└─ cnv_moi(sample, variant)          one child's call, or nothing
   ├─ affected child?     unaffected, or no parent in the family (a founder) -> nothing
   ├─ modellable?         chrM, a chrX/chrY record straddling a PAR boundary, unknown sex on
   │                      non-PAR X/Y, a daughter on non-PAR Y -> nothing
   ├─ unknown_cn?         the child has no CN, or (for a carrier) none of the parents whose
   │                      copies matter has one; a parent in the VCF without CN otherwise counts
   │                      as missing, like a parent missing from the PED (as SNV/Radiant read a
   │                      parent's no-call)
   ├─ carrier?            CN == expected CN -> nothing
   └─ TRIO_TABLE          (the child's deviation, its transmission outcome; see below) -> the
      │                   call, e.g. denovo, inherited_maternal, recessive, possible_denovo; for
      │                   an "undecided" outcome: mendelian_inconsistent if the child's CN can't
      │                   come from the parents, inheritance_unresolved otherwise
      └─ on non-PAR chrX  the X-linked name (X_LINKED_CALLS):
                          son or daughter: denovo -> x_linked_denovo
                          daughter: recessive -> x_linked_recessive (both X copies hit)
                          (a single inherited X copy keeps inherited_*, a son's like a
                          daughter's: dominant or recessive would depend on the zygosity and
                          on who is affected, and a son's gain, CN 2, is neither)

The call looks at the child and its parents only. Who is affected elsewhere in the family (is
the transmitting parent affected, do sibs carry the CNV) is left to whoever reads the tags.
A parent who passes nothing (a father's X to a son, any mother's Y) is read as "normal", and
their CN isn't needed, even when absent from the PED or without CN (harness X14-X16). Here remember that --sample-expr will call cn_po_origin() for each family member(sample) for each compared tag.
For a trio, that is 3 family members x 8 possible tags = 24. In practice

cn_po_origin(sample, variant)       maternal / paternal / both / ambiguous / denovo /
                                    possible_denovo / possible_maternal / possible_paternal, or
                                    nothing; for every child, affected or not
├─ carrier?                         expected CN known, a usable CN, and CN != expected; else nothing
└─ the TRIO_TABLE row's parent of origin: the same row as the MoI call, so MoI and PO always agree
   └─ get_transmission_outcome()    * get_transmission_outcome(): if finds that "no parent in the family"
      │                               returns "undecided" (no tag)
      ├─ get_parent_transmission()  what each parent can pass: its two copies (CN 3 = [2,1]), a
      │                             father's single X/Y, or nothing (a father's X to a son, any
      │                             mother's Y: counts as normal). CN >= 4 can't be split.
      │                             A copy is a "hit" if it changed the child's way (a deleted copy
      │                             for a loss, an extra copy for a gain).
      ├─ both parents known          * needs both parents' copies (a parent who passes nothing
      │                               counts). With a parent absent or without CN, the duo step
      │                               below decides.
      │                             every way mom's copy + dad's copy = the child's CN:
      │                             no way, both can only pass normal copies -> denovo;
      │                             only mom's copy a hit -> maternal; only dad's -> paternal;
      │                             both -> both (recessive); the ways disagree -> ambiguous
      ├─ duo (one parent missing)   the missing one passed 0, 1 or 2 copies, like a real parent.
      │                             Which of the known parent's copies still fit the child's CN?
      │                             only its normal copy -> possible_denovo;
      │                             only its hit -> maternal / paternal (it surely passed it);
      │                             its hit, or its normal copy -> possible_maternal / possible_paternal.
      │                             e.g. duo kid 1, mom 1 -> possible_maternal (D1);
      │                                  duo kid 0, mom 1 -> maternal (D2);
      │                                  duo kid 1, mom 0 -> maternal, inherited_maternal (D5)
      └─ otherwise                  a parent with CN >= 4, no ordinary way, or a copy changed the
                                    other way -> nothing (and inheritance_unresolved or
                                    mendelian_inconsistent for the MoI call)

Expected CN: 2 on autosomes and in the GRCh38 PARs; on non-PAR chrX 1 for males and 2 for
females; on non-PAR chrY 1 for males. Every rule works on the deviation from it. A record that
crosses a PAR boundary has no single expected CN for a male, so it isn't modelled, for anyone.
